# Event lifecycle

An **event** is the container for everything else — a single conference, meetup, or CFP cycle.
This page traces one from creation to wrap-up and points to where each stage happens. See
[Getting started](getting-started.md#events) for the basics of what an event is and how the
switcher works.

## 1. Created

**+ New event** (next to the sidebar's event switcher, or from
[Workspace → Events](workspace-events.md)) opens the Create Event dialog: name, slug (which drives
its public URLs), type, website, location, timezone, start/end dates, a description, and — to save
retyping them later — a starting set of rooms and tracks. Every event belongs to your
organisation; nothing here is visible to other organisations.

## 2. Configured

Before opening the call for speakers, the usual setup pass covers:

- Rooms, tracks, formats, speaker fields, speaker statuses, and email wording, all in
  [Settings](settings.md).
- Your team's access — inviting colleagues as admins or reviewers.
- Deciding your chase mode (automatic reminders vs. a reviewed inbox) under
  [Settings → Chase inbox](settings.md#chase-inbox).

## 3. Call for speakers open

Building and publishing the [submission form](call-for-speakers.md) opens the event up to public
proposals. A form's own **Open/Closed** status and close date are independent of the *event's*
dates — you can run a CFP that closes well before the event itself, which is the usual pattern.

## 4. Collecting and deciding

Submissions accumulate in [Workspace → Submissions](workspace-submissions.md); see the
[submission lifecycle](submission-lifecycle.md) for the full path from draft to accepted. In
parallel, contacts move through their own [contact lifecycle](contact-lifecycle.md) — from
prospect or first-time submitter through to confirmed, onboarded speaker.

The [dashboard](dashboard.md) is the running summary of how this is going at any point — how many
submissions are in, how many decisions are outstanding, who owes you a bio or headshot.

## 5. Agenda built and published

Once you have accepted sessions, [build the agenda](agenda.md) by scheduling them into rooms and
time slots, resolve any conflicts the app flags, and **Publish** when it's ready for the public
feed and any [embeds](embeds.md) you've set up elsewhere.

## 6. Live

On the day (or days) of the event itself, [Green Room](greenroom.md) becomes the working screen —
who's on now, who's up next, and whether they've checked in.

## 7. Multiple events, one organisation

Nothing here is a hard boundary between events run by the same organisation:

- People carry across events — see [Contact lifecycle](contact-lifecycle.md).
- The sidebar's event filter can show **All events** at once in
  [Workspace](workspace.md) and on an [organisation-wide dashboard](dashboard.md#organisation-board-all-events),
  or narrow everything to just one.
- [Pipeline](pipeline.md) prospects and the contact directory live at the organisation level,
  independent of any single event, ready to be enrolled into whichever one you're running next.
